Анимация в CSS собирается из двух вещей: описания кадров и подключения их к
элементу. Теории тут на пять минут. Дальше идут детали, из-за которых одна
анимация оживляет интерфейс, а другая дёргается и раздражает.

Ниже: как сделать анимацию, чем `animation` отличается от `transition`, почему
движение тормозит и что добавилось в CSS за последние пару лет. Добавилось
немало, и пару привычных JS-костылей можно выбросить.

## Как сделать анимацию в CSS

Сначала описываете кадры в правиле `@keyframes`: что происходит в начале и в
конце. Потом подключаете их свойством `animation`. Имя и длительность
обязательны, остальное по необходимости.

```css
/* 1. описываем кадры */
@keyframes fadeIn {
	from {
		opacity: 0;
	}
	to {
		opacity: 1;
	}
}

/* 2. подключаем к элементу */
.card {
	animation: fadeIn 0.5s ease both;
}
```

Кадров может быть сколько угодно. Вместо `from` и `to` пишите проценты: `0%`,
`50%`, `100%`.

Слово `both` в конце задаёт `animation-fill-mode`. Без него элемент мигнёт. До
старта он покажется в обычном виде, а после анимации вернётся к нему же. С
`both` он держит первый кадр до старта и последний после финиша.

Свои кадры удобнее собирать ползунками, результат видно сразу:

/tools/css-keyframes-generator

## animation или transition

Разница в том, кто запускает движение.

Transition ждёт события: наведения, клика, нового класса. И переходит только
между двумя состояниями, из А в Б.

Animation запускается сама, без всяких событий. Кадров у неё сколько угодно, и
крутиться она может бесконечно.

На практике я выбираю так. Наведение и клик закрываю `transition`. Лоадер,
пульсацию и появление при загрузке страницы делаю через `animation`.

```css
/* Наведение: хватает transition */
.button {
	transition: transform 0.2s ease;
}

.button:hover {
	transform: translateY(-2px);
}

/* Непрерывное движение: нужен animation */
.loader {
	animation: spin 0.8s linear infinite;
}
```

## Готовые анимации для копирования

### Появление элемента

Её ставят чаще всех остальных. Блок всплывает снизу и проявляется.

```css
@keyframes fadeInUp {
	from {
		opacity: 0;
		transform: translateY(12px);
	}
	to {
		opacity: 1;
		transform: none;
	}
}

.card {
	animation: fadeInUp 0.5s ease both;
}
```

### Пульсация

Тянет взгляд к кнопке или значку с новыми уведомлениями. Крутится бесконечно,
поэтому на текст её не вешайте: читать то, что пульсирует, невозможно.

```css
@keyframes pulse {
	0%,
	100% {
		transform: scale(1);
		opacity: 1;
	}
	50% {
		transform: scale(1.08);
		opacity: 0.8;
	}
}

.badge {
	animation: pulse 1.5s ease-in-out infinite;
}
```

### Спиннер загрузки

Здесь нужна только `linear`. С любой другой кривой спиннер притормаживает на
стыке оборотов, и это видно.

```css
@keyframes spin {
	to {
		transform: rotate(360deg);
	}
}

.loader {
	width: 2.5rem;
	height: 2.5rem;
	border: 3px solid currentColor;
	border-top-color: transparent;
	border-radius: 50%;
	animation: spin 0.8s linear infinite;
}
```

### Мерцание скелетона

Серая заглушка на месте контента, который ещё грузится. Двигается градиент, а
размеры стоят на месте, поэтому вёрстка не пересчитывается.

```css
@keyframes shimmer {
	from {
		background-position: -200% 0;
	}
	to {
		background-position: 200% 0;
	}
}

.skeleton {
	background: linear-gradient(90deg, #e5e7eb 25%, #f3f4f6 50%, #e5e7eb 75%);
	background-size: 200% 100%;
	animation: shimmer 1.4s linear infinite;
}
```

### Встряска при ошибке

Поле дёргается влево-вправо, и человек без подписи понимает, что пароль не
тот.

```css
@keyframes shake {
	0%,
	100% {
		transform: translateX(0);
	}
	20%,
	60% {
		transform: translateX(-6px);
	}
	40%,
	80% {
		transform: translateX(6px);
	}
}

.input.error {
	animation: shake 0.4s ease;
}
```

### Каскад: элементы появляются по очереди

Номер элемента удобно передать переменной прямо из разметки, а задержку
посчитать в `calc()`. Регистрация через `@property` тут не обязательна, `calc()`
справится и с обычной переменной. Регистрация даёт `--i` тип и значение по
умолчанию: элемент, которому номер забыли проставить, стартует без задержки.

```css
@property --i {
	syntax: '<number>';
	inherits: false;
	initial-value: 0;
}

.item {
	animation: fadeInUp 0.4s ease both;
	animation-delay: calc(var(--i) * 0.08s);
}
```

```html
<li class="item" style="--i: 0">Первый</li>
<li class="item" style="--i: 1">Второй</li>
<li class="item" style="--i: 2">Третий</li>
```

## Почему анимация дёргается

В девяти случаях из десяти анимируются свойства, которые меняют вёрстку.

Если меняются `width`, `height`, `margin`, `top` или `left`, браузер на каждом
кадре заново раскладывает страницу. `transform` и `opacity` браузер может отдать
видеокарте, раскладка от них не меняется.

```css
/* Плохо: браузер пересобирает раскладку 60 раз в секунду */
@keyframes slideBad {
	from {
		left: 0;
	}
	to {
		left: 200px;
	}
}

/* Хорошо: работа уходит на видеокарту */
@keyframes slideGood {
	from {
		transform: translateX(0);
	}
	to {
		transform: translateX(200px);
	}
}
```

То же с увеличением: `scale()` вместо изменения `width` и `height`.

### will-change: не оставляйте его в CSS

Это свойство часто советуют «для оптимизации» и прописывают навсегда. Зря. Оно
держит элемент на отдельном слое всё время, пока висит в CSS, и всё это время
занимает память видеокарты. Сотня карточек с `will-change` на одной странице
работает хуже, чем без него.

Включайте его, когда анимация вот-вот начнётся.

```css
/* Плохо: слой висит всё время */
.card {
	will-change: transform;
}

/* Хорошо: слой готовится, когда курсор уже в списке */
.list:hover .card {
	will-change: transform;
}
```

Старый хак `transform: translateZ(0)` делал то же самое, только без спроса. Он
остался со времён, когда браузеры сами слои не выделяли, и сейчас его копируют
по привычке.

## Доступность и prefers-reduced-motion

Некоторые люди отключают анимации в настройках системы: их укачивает, у них
мигрени или вестибулярные нарушения. Им от прыгающего интерфейса буквально
плохо.

Эту настройку надо учитывать. В WCAG это отдельный критерий (2.3.3), а не
вежливость дизайнера.

```css
@media (prefers-reduced-motion: reduce) {
	*,
	*::before,
	*::after {
		animation-duration: 0.01ms !important;
		animation-iteration-count: 1 !important;
		transition-duration: 0.01ms !important;
		scroll-behavior: auto !important;
	}
}
```

Честнее включать анимацию только тем, кто не против:

```css
@media (prefers-reduced-motion: no-preference) {
	.card {
		animation: fadeInUp 0.5s ease both;
	}
}
```

В первом варианте анимация есть у всех, а потом её «глушат». Во втором её по
умолчанию нет вовсе. Для бесконечных анимаций вроде пульсации я бы брал только
второй: на них жалуются чаще всего.

## Плавность: функции времени

От кривой скорости зависит, выглядит движение живым или как у робота.

- `linear` держит скорость постоянной. Годится разве что для вращения.
- `ease-out` стартует быстро и мягко тормозит. Для интерфейса подходит чаще
  других: элемент влетает и плавно останавливается.
- `ease-in`, наоборот, разгоняется к концу. Хорош для исчезновения.
- `ease-in-out` разгоняется и тормозит, это для движения туда-обратно.

Если стандартных не хватает, задайте свою кривую четырьмя числами в
`cubic-bezier()`. Подбирать их вслепую мучительно, проще тянуть контрольные
точки мышью:

/tools/css-bezier-curve-generator

### linear(): пружины и отскоки

`cubic-bezier` рисует одну плавную дугу, настоящий отскок им не описать. Для
этого есть функция `linear()`. Она строит кривую по точкам, так что пружину,
отскок или затухающие колебания можно задать набором значений.

```css
.bounce {
	transition: transform 0.6s
		linear(0, 0.004, 0.016, 0.325 26.5%, 0.63, 0.815 61%, 0.933, 0.987, 1);
}
```

Выглядит страшно, но руками такое никто не пишет, кривые генерируют.

## Что появилось в CSS недавно

Ради некоторых эффектов годами подключали JavaScript. Теперь хватает CSS.

### @starting-style: появление из display: none

Элемент с `display: none` нельзя было плавно показать. Анимировать не от чего,
у браузера нет предыдущего состояния, элемента просто не было на странице.
`@starting-style` задаёт это стартовое состояние явно.

```css
.popup {
	opacity: 1;
	transition:
		opacity 0.3s ease,
		display 0.3s allow-discrete;
}

/* Состояние, из которого элемент появляется */
@starting-style {
	.popup {
		opacity: 0;
	}
}

.popup[hidden] {
	opacity: 0;
	display: none;
}
```

Так же оживают модалки, поповеры и `<dialog>`, всё, что раньше появлялось
рывком.

### @property: анимация переменных и градиентов

Обычную CSS-переменную анимировать нельзя. Для браузера это строка символов, а
не цвет или угол. Промежуточные значения он посчитать не может и переключает
переменную скачком посередине.

`@property` сообщает браузеру тип. Зарегистрированная переменная анимируется, и
без JavaScript получаются вращающийся градиент, плавный поворот угла, счётчики.

```css
@property --angle {
	syntax: '<angle>';
	inherits: false;
	initial-value: 0deg;
}

@keyframes rotate-gradient {
	to {
		--angle: 360deg;
	}
}

.card {
	background: conic-gradient(from var(--angle), #6366f1, #ec4899, #6366f1);
	animation: rotate-gradient 3s linear infinite;
}
```

Как устроены сами переменные, я разбирал в статье про
[CSS custom properties](/blog/css-variables).

### Анимации по скроллу без JavaScript

Появление при прокрутке раньше делали через `IntersectionObserver`. Теперь
анимацию можно привязать к скроллу прямо в CSS.

```css
@keyframes reveal {
	from {
		opacity: 0;
		transform: translateY(2rem);
	}
	to {
		opacity: 1;
		transform: none;
	}
}

.section {
	animation: reveal linear both;
	animation-timeline: view();
	animation-range: entry 0% cover 40%;
}
```

Firefox долго держал это за флагом и включил по умолчанию только в версии 159
(октябрь 2026). Теперь анимации по скроллу работают во всех основных браузерах,
но у кого-то ещё стоит старая версия. Ничего страшного: без поддержки элемент
просто будет видимым с самого начала.

## Сколько должна длиться анимация

С этих цифр удобно начинать подбор:

- 100–200 мс на реакцию на наведение и нажатие. Быстрее движение не заметят,
  медленнее покажется, что интерфейс подвисает.
- 200–500 мс на появление элементов и раскрытие панелей.
- 500–1000 мс на крупные переходы и смену экранов.

Больше секунды уже выглядит как тормоза, даже если красиво.

## Отладка

В DevTools есть панель Animations. Она ловит все запущенные анимации, их можно
поставить на паузу, промотать по кадрам, замедлить и тут же подправить кривую.
Гораздо удобнее, чем вписывать `animation-duration: 10s` и смотреть в
замедлении.

Потом проверьте, не просела ли скорость страницы. Тяжёлые анимации часто тянут
метрики вниз, а как эти метрики складываются в итоговую оценку, я разбирал в
статье про [оценку Lighthouse](/blog/lighthouse-100).

## Коротко

- `transition` запускается событием, `animation` сама.
- Анимируйте `transform` и `opacity`. Всё остальное заставляет браузер
  пересчитывать вёрстку на каждом кадре.
- `will-change` включают перед анимацией и снимают после, а не держат в CSS
  постоянно.
- `prefers-reduced-motion` учитывать обязательно.
- Переменную нельзя анимировать без `@property`.
- Появление из `display: none` теперь делается на CSS через `@starting-style`.
